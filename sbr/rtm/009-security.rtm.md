# Requirements Traceability Matrix — Cross-Cutting API Security (Adversarial Audit)

- **Source**: no single `spec.md` — this RTM audits *every* externally-reachable endpoint (all 10
  gRPC services in `api/proto/ubertool_trusted_backend/v1/*.proto`, plus the one plain-HTTP
  endpoint in `internal/api/http/image_upload_handler.go`) against attacker-chosen inputs and
  identities, independent of any single feature's functional spec. Functional correctness for
  each domain is already tracked in `sbr/rtm/001..008-*.rtm.md`; this file is the adversarial
  complement — "does the requirement hold when the caller is hostile?" — not a restatement of
  those FRs.
- **Tier mapping in effect**: `sbr/README.md` → "This repo's adapter" (L1=`tests/unit`,
  L2=`tests/integration`, L3=`tests/e2e`, Grounding=`tests/smoke`+`tests/e2e` journeys).
- **Generated**: 2026-07-23, manual adversarial code-review audit (not a live penetration test —
  no traffic was sent to a running instance; every finding below is a static-analysis claim
  verified by direct file:line inspection of the current `spec-kit` branch).
- **Updated 2026-07-23 (regression tests)**: tests added for 8 of the 9 `Vulnerable` findings
  (SEC-BILL-004/006 counted once) proving each gap — 5 as red (secure-behavior-asserting,
  failing) tests, 3 as green documenting tests for the findings that were genuine product-policy
  questions (SEC-ORG-002, SEC-TOOL-002, SEC-ADMIN-002). No application code was changed in this
  pass.
- **Updated 2026-07-23 (fixes applied)**: all 9 `Vulnerable` findings are now fixed in code and
  regression-locked — reclassified `Complete` below, except SEC-ORG-002, which the reviewer
  confirmed as an intentional product decision and which is reclassified `Accepted Risk` instead
  (see that row's Notes). SEC-TOOL-002 and SEC-ADMIN-002 were resolved per explicit reviewer
  decisions (shared-org scoping for `GetTool`; a SUPER_ADMIN-only rank check for blocking an
  ADMIN/SUPER_ADMIN) rather than unilaterally by the audit. Every fix was made without touching
  any proto/gRPC request or response field — no API contract change was required for any of the
  9 findings. Full unit suite and full integration suite (against a live Postgres instance) pass
  with zero failures after these fixes.
- **Mode**: adversarial audit — see "Boundary Status vocabulary" below for how this differs from
  the standard SBR audit-mode vocabulary in `sbr/README.md`.

## Methodology

For each RPC/HTTP endpoint: (1) read the proto/route contract and its configured security level
(`internal/config/security_config.go`); (2) read the handler and service-layer code to find what
authorization check, if any, gates the specific resource the request targets; (3) enumerate
concrete attack vectors grounded in the actual request fields and code paths (not generic OWASP
boilerplate); (4) grep `tests/unit`, `tests/integration`, `tests/e2e`, `tests/smoke` — including
e2e subtest string literals, since most e2e coverage lives in `t.Run("...")` subtests nested
under one `Test<Service>_E2E` function per domain — for a test that would actually catch each
attack; (5) classify.

### Boundary Status vocabulary (extends `sbr/README.md`)

A standard SBR audit assumes the requirement is correctly implemented and only asks "is there a
test?". An adversarial audit cannot make that assumption — the first question is "does a defense
exist at all?" — so this RTM uses two additional statuses beyond `sbr/README.md`'s
`Complete`/`Gap`/`Unclassified`:

- **`Vulnerable`** — the attack **succeeds against current code**. This is a live security defect,
  not a test gap: fix the code first, then add the regression test. Severity tag
  (Critical/High/Medium/Low) follows in parentheses.
- **`Accepted Risk`** — the "attack" succeeds, but it is a deliberate, already-documented product
  decision (confirmed by an existing test that locks in the behavior as intended, e.g. a
  code comment or test name saying "documents current non-enforcement"). Listed so a reviewer can
  re-confirm the tradeoff is still acceptable, not because it's a new discovery.
- **`Complete`** — a defense exists in code **and** a test regression-locks it against the specific
  attack vector.
- **`Gap — <tier>`** — a defense exists in code but no test proves it fails to be defeated (same
  meaning as `sbr/README.md`).
- **`Unclassified`** — could not be confidently resolved; flagged for human review.

  cause) are fixed and regression-locked as of 2026-07-23 — see "Fix log" below. 8 reclassified
  `Complete`; 1 (`SEC-ORG-002`) reclassified `Accepted Risk` per explicit reviewer decision.
- **`Accepted Risk` (intentional, tested-as-designed, flagged for re-confirmation)**: 6 —
  `SEC-ORG-001` (public `SearchOrganizations` PII), `SEC-ORG-002` (`GetOrganization` no
  membership gate — reviewer-confirmed 2026-07-23, redundant with SEC-ORG-001's own exposure),
